# Release v1.3.1: actix-web Out of the Dependency Tree
**Date:** 2026-10-09
**Compare:** `v1.3.0...v1.3.1`

## Summary

Dependency hygiene patch. **No API or behavior changes** in the library;
upgrading needs no code changes.

`lang-lib` 1.3.0 listed `actix-web` as an optional dependency, used only to
build the actix-web example behind the `web-example-actix` feature. Through
it, `cargo audit` reported `time` 0.3.45 (RUSTSEC-2026-0009) and `h2`
0.3.27 (RUSTSEC-2026-0258) against lang-lib. Neither was reachable from a
normal build, but any project enabling the feature pulled them in, and the
advisories showed up in lang-lib's audit.

`1.3.1` removes `actix-web` from lang-lib's dependencies entirely.

## Changed

- The actix-web example is now a standalone crate in `examples/web-actix`,
  depending on lang-lib by path. It is not part of lang-lib's package or
  dependency graph.

  ```bash
  cargo run --manifest-path examples/web-actix/Cargo.toml
  ```

  The example builds `actix-web` without its `http2` feature (it serves
  HTTP/1.1, so `h2` is not compiled) and resolves a patched `time`, which
  needs Rust 1.88. lang-lib itself stays on Rust 1.85.
- `web-example-actix` remains as an empty feature for compatibility. It no
  longer enables anything.
- CI: the example crate gets its own fmt, clippy and build checks on stable,
  and a new MSRV job runs the library's tests on Rust 1.85.

## Compatibility

- **Source compatible** with `1.3.0`. `cargo semver-checks` reports no
  public API change.
- **MSRV:** Rust `1.85`, unchanged.
- `--features web-example-actix` still resolves, but the actix example is no
  longer built through it; use the command above.

## Migration from 1.3.0

```toml
[dependencies]
lang-lib = "1.3.1"
```
